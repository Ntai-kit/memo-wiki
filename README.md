# Memo Wiki

Wikipediaのようにページ同士をリンクでつなげられる、デスクトップ用のメモアプリである。
リンクの設定や画像の挿入は、Wiki記法のようなテキスト入力ではなく、**ボタンのクリックや貼り付けなどの直感操作**で行う。

## 主な機能

- **ページ間リンク**: 文字を選択して「🔗 リンク」ボタンを押し、一覧からリンク先ページをクリックで選択。選択中の文字から新規ページを作ってリンクすることも可能
- **Webサイトのリンク**: 同じダイアログで「表示する文字」と「リンク先URL」を入力し、3つの形式から挿入方法をクリックで選ぶ。
  文字を選択してからダイアログを開けば、その文字が表示文字の初期値になる(`Ctrl+K` でも開く)。
  貼ったリンクは **Ctrl+クリック** で表示文字・リンク先を編集したり解除したりできる
  - **🔗 文字にリンク**: 任意の文字にURLを埋め込む(クリックで既定ブラウザが開く)
  - **🃏 カード**: ページのタイトル・説明・サムネイルを自動取得してカード状に表示
  - **📺 埋め込み**: iframeでメモ内に埋め込み表示。YouTube・Vimeo・ニコニコ動画・GoogleマップはURLを自動で埋め込み用に変換し、動画はメモ内で再生できる
- **画像の挿入**: 「🖼 画像」ボタンでのファイル選択、Ctrl+V での貼り付け、ドラッグ&ドロップの3通り
- **トップ画像・サブタイトル**: ページ上部に大きなカバー画像を置ける(「🖼 トップ画像を追加」ボタンで選択、あとから変更・削除も可能)。タイトル下には1行の説明(サブタイトル)を書け、ページ一覧にも表示される
- **関連マップ**: ページ同士のリンク関係を図として閲覧できる。丸=ページ、矢印=リンクの向き、丸の大きさ=つながりの多さ、灰色=どこともつながっていないページ。丸をクリックするとそのページが開く。ドラッグで移動、ホイールで拡大縮小
- **書式設定**: 見出し・太字・箇条書きをツールバーから設定
- **検索・ページ一覧**: サイドバーでページ一覧の表示と、タイトル・本文の全文検索
- **保存**: 「💾 保存」ボタンまたは Ctrl+S。ページ移動時は自動保存

## 動かし方

Node.js(v18以上推奨)がインストールされていることが前提である。

```bash
cd memo-wiki
npm install   # 初回のみ(Electronをダウンロードする)
npm start     # アプリが起動する
```

## 実行ファイル(.exe)の作り方

Windows上で以下を実行すると、`release/` フォルダに実行ファイルが生成される。

```bash
cd memo-wiki
npm install    # 初回のみ
npm run dist   # ビルド実行(数分かかる)
```

生成されるファイル:

- `release/MemoWiki-Setup-<バージョン>.exe` — インストーラ。ダブルクリックでインストールし、デスクトップとスタートメニューにショートカットが作られる

自動更新に対応させるため、配布形式はインストーラ版に統一している(ポータブル版は自動更新できない)。
コード署名をしていないため、初回起動時にWindowsのSmartScreen警告が出ることがある。その場合は「詳細情報」→「実行」を選ぶ。

アイコンは `build/icon.ico` を差し替えれば変更できる(256x256を含むマルチサイズICO)。
ビルド設定は `package.json` の `build` セクションにまとまっている。

## アップデート(自動更新)

アプリは起動から数秒後と6時間ごとに新しいバージョンを自動で確認する。
見つかると裏でダウンロードし、準備ができたら画面右下に
「バージョン x.y.z の準備ができました」というバーが出る。
**「再起動して更新」を押せばその場で更新**され、押さずに閉じても
次にアプリを終了したときに自動で適用される(編集中に勝手に再起動することはない)。

配信にはGitHub Releasesを使う。導入は初回だけ次の3ステップで済む。

### 1. GitHubリポジトリを用意する(初回のみ)

1. GitHubで `memo-wiki` という名前の**パブリック**リポジトリを作る
2. `package.json` の `build.publish.owner` を自分のGitHubユーザー名に書き換える
   ```json
   "publish": [{ "provider": "github", "owner": "自分のユーザー名", "repo": "memo-wiki" }]
   ```
3. このフォルダをそのリポジトリにpushする(`.gitignore` は用意済み)

### 2. 公開用トークンを用意する(初回のみ)

> トークンを手元に置きたくない場合は、この手順を飛ばして
> `.github/workflows/release.yml` を使う方法もある(下の「更新を公開する」参照)。
> そちらの方が安全なので、慣れてきたら乗り換えるとよい。


GitHubの Settings → Developer settings → Personal access tokens で
`repo` 権限のトークンを作り、環境変数に設定する。

```
setx GH_TOKEN あなたのトークン
```

`setx` で設定した値は**次に開いたコマンドプロンプトから**有効になる。

### 3. 更新を公開する(毎回)

ソースを変更したら `package.json` の `version` を上げて(例: 1.3.0 → 1.4.0)、
次の1コマンドを実行するだけでよい。

```bash
npm run release
```

ビルドとGitHub Releasesへのアップロードが自動で行われる。
公開されたリリースは最初「下書き(draft)」状態なので、
GitHubのReleasesページで **Publish release** を押すと配信開始になる。
以降、各PCのアプリが自動で気づいて更新する。

なお `npm run dist` は今までどおり、公開せずに手元でexeを作るだけのコマンドである。

#### トークンを使わない公開方法(推奨)

`.github/workflows/release.yml` を入れてあるので、
バージョンを上げてタグをpushするだけでも公開できる。

```bash
git add -A && git commit -m "v1.4.0"
git tag v1.4.0
git push && git push origin v1.4.0
```

ビルドはGitHubのWindows環境で走り、公開まで自動で終わる。
自分のPCにトークンを保存しなくて済むため、こちらの方が安全である。

### 注意点

- 自動更新が働くのは**インストーラ版(NSIS)**のみ。ポータブル版は仕組み上対応できないため、配布対象から外した
- 今インストールされている v1.1.0 には更新機能がまだ入っていないので、
  **v1.3.0 だけは手動でインストールし直す必要がある**。それ以降は自動になる
- `npm start` での開発中は自動更新は動かない(更新情報が埋め込まれていないため)。異常ではない

## データ保護(更新してもメモは消えない)

**メモのデータはアプリ本体とは別の場所(下記「データの保存場所」)にあるため、
更新やアンインストールでは消えない。** さらに次の2つの保護が組み込まれている。

1. **更新時の自動バックアップ**: バージョンが変わって最初の起動時に、
   データフォルダ全体が `backups/v旧バージョン-日時/` にコピーされる(最新5世代を保持)。
   万一のときはバックアップフォルダの中身を `data/` に戻せば復元できる。
2. **形式バージョンと自動移行**: 各ページのJSONに `formatVersion` が記録されており、
   将来ファイル形式を変更しても、旧形式のページは読み込み時に自動で新形式に変換される。
   形式を変更するときの実装手順は `src/main/storage.js` 冒頭のコメントを参照
   (`FORMAT_VERSION` を+1して `MIGRATIONS` に変換関数を1つ足すだけ)。

## データの保存場所

ページと画像はアプリのユーザーデータフォルダ内の `data/` に保存される。

- Windows: `%APPDATA%\memo-wiki\data\`
- macOS: `~/Library/Application Support/memo-wiki/data/`
- Linux: `~/.config/memo-wiki/data/`

```
data/
├── pages/    # 1ページ = 1つのJSONファイル
│             #   { formatVersion, id, title, subtitle, cover, html, updatedAt }
└── images/   # 貼り付けた画像・トップ画像のファイル
```

本文中の画像は `memo://images/ファイル名` という相対的なURLで参照するため、`data/` フォルダごとコピーすればそのままバックアップ・移行できる。

## コード構成(機能ごとにモジュール分割)

```
src/
├── main/                 # メインプロセス(Node.js側)
│   ├── main.js           # エントリポイント。ウィンドウ生成と各モジュールの初期化のみ
│   ├── storage.js        # ページ・画像のファイル入出力と検索
│   ├── ipc.js            # レンダラーとの通信(IPCハンドラの登録)
│   ├── protocol.js       # memo:// スキームで画像を配信
│   ├── metadata.js       # リンクカード用のOGPメタデータ取得
│   ├── backup.js         # アップデート時の自動バックアップ
│   └── updater.js        # 自動アップデート(GitHub Releasesの確認とダウンロード)
├── preload.js            # レンダラーに公開する安全なAPI(window.memoAPI)
└── renderer/             # 画面側
    ├── index.html        # 画面のレイアウト
    ├── styles.css        # スタイル
    └── js/
        ├── app.js        # まとめ役。状態管理と各モジュールの連携のみ
        ├── api.js        # window.memoAPI の薄いラッパー
        ├── editor.js     # 本文エディタ(contenteditable)の操作
        ├── cover.js      # トップ画像とサブタイトル
        ├── links.js      # リンク設定ダイアログとリンククリック処理
        ├── embeds.js     # リンクカード・iframe埋め込みのHTML生成
        ├── graph.js      # 関連マップの描画とマウス操作
        ├── graph-layout.js # 関連マップのノード配置計算(力学モデル)
        ├── images.js     # 画像の保存と挿入
        ├── paste.js      # 貼り付け・ドロップの受け口(内容を振り分ける)
        ├── sanitize.js   # 貼り付けHTMLの浄化(危険な要素を除去)
        ├── pages.js      # サイドバーのページ一覧
        ├── search.js     # 検索ボックス
        └── updates.js    # 自動アップデートの通知バー
```

### 機能追加の手順

新しい機能(例: タグ付け)を追加する場合の典型的な流れ:

1. `storage.js` にデータ操作の関数を追加する
2. `ipc.js` にチャンネルを1行追加する(命名は `対象:操作`)
3. `preload.js` に対応するAPIを1行追加する
4. `renderer/js/` に新しいモジュール(例: `tags.js`)を作る
5. `app.js` の `main()` でそのモジュールを初期化する

各モジュールは自分の責務だけを持ち、モジュール間のやり取りは
`app.js` がコールバックで橋渡しする構成になっている。

### 埋め込み対応サイトの追加方法

`renderer/js/embeds.js` の `EMBED_RULES` 配列に
「URLのパターン」と「埋め込みURLへの変換」を1つ追加するだけでよい。

### 関連マップの見た目を調整する

- ノードの色・大きさ: `renderer/js/graph.js` の `COLORS` と `BASE_RADIUS` などの定数
- 配置の詰まり具合: `renderer/js/graph-layout.js` の `REPULSION`(反発)、
  `SPRING_LENGTH`(リンクの理想距離)などの定数

配置計算(`graph-layout.js`)は画面に依存しない純粋な計算なので、
描画を変えずにレイアウトだけ差し替えることもできる。

## セキュリティとライセンス

自動アップデートを持つアプリなので、**配信元(GitHubリポジトリ)を守ること**が
最も重要になる。設定手順と、アプリ本体に入れてある防御の一覧は
[SECURITY.md](SECURITY.md) にまとめてある。最低限やることは次の3つ。

1. GitHubアカウントの**2段階認証**を有効にする
2. `main` ブランチを保護する(force push と削除を禁止)
3. 公開用トークンは**このリポジトリ限定・期限付き**にし、絶対にコミットしない
   (`.github/workflows/release.yml` を使えば、そもそも手元にトークンを置かずに公開できる)

アプリ本体には、外部からコピーしたHTMLや埋め込みページが混ざっても被害が出ないよう、
プロセス隔離・遷移の禁止・CSP・貼り付けHTMLの浄化などを多層で入れてある(詳細はSECURITY.md)。

なお**ソースコードのコピーや解析そのものは技術的に防げない**。
Electronアプリは実行ファイルを展開すればJavaScriptが読めるため、
難読化しても解析は防げず可読性を損なうだけなので採用していない。
そこはライセンスで条件を課す領域と割り切っている。

## 既知の制限

- 本文中のリンクは普通にクリックすると開く/移動する仕様のため、リンク自体を編集したいときは **Ctrl+クリック**(またはリンクを選択して `Ctrl+K`)を使う
- 書式設定に `document.execCommand` を使用している(非推奨APIだが、Electron/Chromiumでは安定して動作する)
- iframe埋め込みは、サイト側が埋め込みを禁止している場合(X-Frame-Options等)は表示されない。その場合はリンクカードを使う
- リンクカードのサムネイルは元サイトのURLを参照しているため、オフライン時は画像部分だけ表示されない
- 関連マップに出るのは内部リンク(ページ同士のリンク)だけで、外部サイトへのリンクは含まれない
- トップ画像を「削除」しても画像ファイル自体は `images/` に残る(誤操作から戻せるようにするため)
- Webページから貼り付けたHTMLは安全のため一部の装飾(色・フォント・レイアウト指定)が落ちる。文章の構造(見出し・リスト・表・リンク・画像)は保たれる
